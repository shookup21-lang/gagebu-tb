### 스크립트 스코프 주의사항

메인 스크립트의 최상위 `let records`, `const APP_BUILD` 등은 **window 속성이 아닙니다.** (classic script의 top-level `let`/`const`는 전역 렉시컬 환경에 들어감) 다른 `<script>` 블록에서는 이름으로 그대로 접근되지만, `window.records`로는 접근되지 않습니다. 테스트 코드를 짤 때 `w.eval('records')`를 쓰세요.

반면 `function foo(){}`로 선언한 것은 window 전역이므로 `onclick="foo()"`가 동작합니다.

## 4. 데이터 모델

### 4-1. 거래 기록 (핵심)

localStorage 키 `tdbr_v3`에 배열로 저장. 전역 변수 `records`가 메모리 사본.

```js
{
  id: 1757834400123,   // Date.now() — 유일 식별자
  date: '2026-09-14',  // YYYY-MM-DD
  type: '일반',        // '일반' | '신용' 등
  cat: '지출',         // 대분류 — 아래 5개 고정
  mid: '식비',         // 중분류
  sub: '외식',         // 소분류
  place: '김밥천국',   // 소제목 (필수)
  content: '점심',
  income: null,        // 숫자 또는 null (음수 = 수입 취소)
  expense: 9000,       // 숫자 또는 null (음수 = 환불)
  pay: '국민카드',     // 지불수단 (계좌명 또는 카드명)
  note: '',
  discount: null,
  discountPct: null,
  memo: ''
}
```

필수값: `date`, `cat`, `place`, 그리고 `income`/`expense` 중 하나.

**대분류는 5개 고정입니다.** 사용자가 추가·삭제할 수 없습니다.
`수입` `이체대체` `지출` `저축` `대출`

**음수 금액을 지원합니다.** 지출이 음수면 환불(초록 +), 수입이 음수면 수입 취소(빨강 −)로 표시됩니다. `fmtSignedAmount()` 참고.

### 4-1-1. 저장소 접근은 반드시 `STORE`로 ⚠️

앱의 모든 저장소 접근은 전역 `STORE`를 통한다. 휴대폰(local 모드)에서는 `localStorage`, PC 모드에서는 `sessionStorage`다. **`localStorage`를 직접 쓰면 PC 모드에서 가계부가 PC에 남는 사고가 난다.** 예외는 민감하지 않은 기기 설정 세 가지뿐이며, 이들은 `window.localStorage`로 명시해서 쓴다: `tdbr_theme`, `tdbr_device_mode`, `tdbr_gate_name`.

### 4-2. localStorage 키 전체 (9개, 백업 대상)

| 키 | 내용 | 형태 |
|---|---|---|
| `tdbr_v3` | 거래 기록 본체 | 배열 |
| `tdbr_v3_categories` | 분류 | `{대분류: {중분류: [소분류...]}}` |
| `tdbr_default_categories` | 초기설정 스냅샷 | 객체 |
| `tdbr_card_settings` | 카드 설정 | `[{card, payDay, startDay, endDay}]` |
| `tdbr_pay_general` | 내 지갑(계좌) | 문자열 배열 |
| `tdbr_settings` | 일반 설정 | 객체 |
| `tdbr_savings_accounts` | 저축 | `[{name, sub, start}]` |
| `tdbr_loans_accounts` | 대출 | `[{name, sub, start}]` |
| `tbdr_settings_saved` | 설정 스냅샷(구버전 호환) | 객체 |

**⚠️ 철자 주의:** 마지막 하나만 `tbdr_`이고 나머지는 `tdbr_`입니다. 오타지만 기존 사용자 데이터가 걸려 있어 고치지 않았습니다. 백업 코드(`BACKUP_KEYS`)는 두 철자를 모두 포함합니다.

**새 키를 만들 때는 `tdbr_`를 쓰고, 반드시 `BACKUP_KEYS` 배열에도 추가하세요.** 빠뜨리면 백업·동기화에서 그 데이터만 조용히 유실됩니다.

백업 대상이 아닌 기기별 키:
`tdbr_theme` `tdbr_storage_limit` `tdbr_sync_name` `tdbr_sync_pass` `tdbr_sync_version` `tdbr_sync_info` `tdbr_sync_dirty`

`tdbr_device_mode`('local'이면 암호 화면 없이 이 기기에 저장해서 씀), `tdbr_gate_name`(PC 모드 암호 화면에서 마지막으로 쓴 이름)은 항상 localStorage.

`tdbr_sync_dirty`: 마지막 동기화 이후 이 기기에서 데이터가 바뀌었으면 시각(ms)이 들어 있다. `save()`와 설정 저장 함수(`_lsSet`)가 켜고, 업로드·불러오기 성공 시 지운다. `tdbr_sync_info`에는 `localAt`(이 기기에서 동기화한 시각 ms)이 추가됐다.

### 4-3. 저장 함수

```js
save()   // records → localStorage. 저장 후 길이 비교로 검증하고,
         // 실패하면 alert 경고 + false 반환. 반드시 반환값을 확인할 것.
         // 실패 시 records를 localStorage에 실제로 저장된 상태로 되돌린다
         // (화면에만 있고 저장은 안 된 '유령 기록' 방지). 성공 시 markLocalDirty().
_lsSet(key, value)   // 설정류(분류·카드·지갑·저축·대출) 저장 공통. 예외 대신 경고 + false.
```

기록을 바꾸는 흐름은 모두 `if(!save()) return;` 형태다. `saveForm()`은 실패하면 입력 화면에 그대로 머물러 입력 내용을 지킨다.

localStorage 용량 한계(기기별 2.5~5MB)를 이진 탐색으로 실측하는 `measureStorageLimit()`이 있고, 결과를 `tdbr_storage_limit`에 캐시합니다. 설정 → 백업과 내보내기 화면에 게이지로 표시됩니다.

**용량 감각:** 기록 5,000건 ≈ 0.97MB. 1만 건 근처에서 한계가 옵니다.

**중복 판정 방식 (2026-09-14 수정됨 — 중요):**
단순히 "내용이 같으면 건너뛰기"가 아니라 **내용별 개수를 세서** 판정합니다.

```js
_bkSig(r) = [date,type,cat,mid,sub,place,content,income,expense,pay].join('|')

// 1) id가 같으면 확실한 중복 → 건너뛰고 해당 서명 카운트 1 감소
// 2) id는 다르지만 내가 이미 같은 서명을 N개 갖고 있으면 → 건너뛰고 카운트 감소
// 3) 그 외 → 추가
```

이 방식이라야 **같은 날 같은 가게에서 두 번 산 정당한 중복 2건**이 살아남으면서, **같은 파일을 두 번 불러와도** 기록이 늘지 않습니다. 예전 방식(서명 존재 여부만 체크)은 정당한 중복을 삼켰습니다. 이 로직을 건드릴 때는 두 시나리오를 모두 테스트하세요.

**한계:** 합치기는 추가만 합니다. **수정·삭제는 전달되지 않습니다.** 한쪽에서 지운 기록이 다른 쪽에 남아 있으면 합칠 때 되살아납니다.

### 6-2. Firebase 동기화 (주력 기능)

**설계 전제: 부부가 동시에 입력하지 않는다.** 그래서 병합 없이 통째로 덮어쓰는 단순 구조입니다.

```
Firestore 컬렉션: ledgers
문서 ID: SHA-256('tbdr-ledger:' + 공유암호) 앞 16바이트 hex
문서 필드: { salt, iv, data, version, updatedBy, updatedAt, recordCount }
```

- `data`는 백업 JSON 전체를 **gzip 압축한 뒤** **AES-GCM 256**으로 암호화 (PBKDF2 SHA-256, 15만 회). 압축했으면 문서에 `z: 'gzip'` 필드가 붙는다. `z`가 없는 예전 문서도 그대로 읽힌다.
- **압축이 필수인 이유:** Firestore 문서 한 개는 최대 1MiB. 압축 없이는 한글 UTF-8 + 이중 JSON 이스케이프 + base64 때문에 **기록 약 2,600건에서 업로드가 막힌다.** 압축 후 5,000건 ≈ 104KB. 업로드 전에 크기를 확인하고, 한계를 넘으면 저장 전에 안내한다.
- 압축은 `CompressionStream`(크롬 80+)을 쓴다. 없으면 압축 없이 올린다.
- 문서 ID 자체가 암호에서 파생되므로 **암호를 모르면 문서 위치조차 찾을 수 없습니다**
- 평문 노출은 `updatedBy`, `updatedAt`, `recordCount`뿐

**순서 뒤바뀜 방지 (중요):**
`version`은 업로드마다 1씩 증가합니다. 기기는 마지막으로 맞춘 버전을 `tdbr_sync_version`에 갖고 있습니다. 업로드 시 서버 version이 내 것보다 크면 상대방이 먼저 저장한 것이므로 경고 후 차단합니다. (강제 덮어쓰기는 2단계 확인 후 가능)

**강제 덮어쓰기 경고:** 서버 문서를 복호화해서 "서버 N건 / 내 기기 M건"과 **서버에만 있는 기록**(id 기준) 목록을 최대 5건 보여준다. 보는 분의 오래된 기기가 입력 담당의 기록을 지우는 사고를 막기 위함.

**불러오기 전 경고:** 이 기기에만 있는 기록(서버에 id가 없고, id가 마지막 동기화 시각 이후인 것)을 목록으로 보여주고, 그런 기록이 없어도 `tdbr_sync_dirty`가 켜져 있으면 "수정·삭제·설정 변경이 사라진다"고 알린다. 잃을 게 있으면 2단계 확인.

**버전 기록 순서:** 불러오기의 `syncSetVer`는 `_bkOverwrite`가 **성공한 뒤에** `after` 콜백으로 실행한다. `_bkOverwrite`는 9개 키를 쓰다 실패하면 원래 값으로 되돌린다.

**서버 규칙이 최종 방어선:** `update`는 `version == 기존 + 1`일 때만 허용된다. 읽고 쓰는 사이에 다른 기기가 먼저 저장하면 서버가 거부하고, 앱은 "먼저 저장했을 수 있습니다" 안내를 띄운다.

관련 함수:
```
syncUpload() / syncDownload() / openSyncSettings() / syncReady() / syncStatusText()
_syncDocId() / _syncKey() / _syncEncrypt() / _syncDecrypt() / _syncErr()
_syncZip() / _syncCanZip() / _syncDecryptRaw() / _syncUnpack() / _syncReadRemote()
syncIsDirty() / syncClearDirty() / markLocalDirty() / _syncRecList()
```

**Firebase SDK는 ESM 모듈로 gstatic CDN에서 로드됩니다.** module script는 deferred라 classic script보다 늦게 실행됩니다. 그래서 `window.TBDR_FB`는 세 가지 상태를 가집니다.

```js
{ configured:false, loading:true }              // SDK 로딩 중
{ configured:true,  load(), save() }            // 준비 완료
{ configured:false, loading:false, error:'…' }  // 실패
```

`syncReady()`는 이 상태와 `crypto.subtle` 존재 여부(https 필수)를 함께 검사합니다. https가 아니면 암호화 API가 없어 동작하지 않습니다.

**Firebase 콘솔 설정 상태 (이미 완료됨):**
- Firestore: asia-northeast3, 프로덕션 모드
- Authentication: 익명 로그인 사용
- 승인된 도메인: `shookup21-lang.github.io`
- 보안 규칙 (`firestore-rules.txt`, 2026-09-19 강화): `ledgers/{docId}`에 **get / create / update만** 허용. **list·delete 금지.** create는 `version == 1`, update는 `version == 기존 + 1`일 때만.
  - list를 막는 이유: 허용하면 누구나(익명 로그인은 누구나 가능) 문서 ID 목록을 받아, ID(=암호의 SHA-256)를 오프라인으로 대입해 암호를 알아낼 수 있다.
  - 공유 암호는 새로 정하거나 바꿀 때 **8자 이상**이어야 한다(기존 짧은 암호는 계속 허용).

`firebaseConfig`의 apiKey가 코드에 노출되는 건 정상입니다. Firebase 웹 설정은 공개 전제이고, 실제 보호는 보안 규칙 + 클라이언트 암호화가 담당합니다.

## 8. 네비게이션 (2026-09-14 추가)

### 안드로이드 뒤로가기

원래 `handleAndroidBack()`은 네이티브 앱(MainActivity.kt)용으로 만들어져 **PWA에서는 아무도 호출하지 않았습니다.** 그래서 뒤로가기를 누르면 앱이 그대로 종료됐습니다. 지금은 `popstate`에 연결돼 있습니다.

동작 방식:
1. 로드 시 히스토리에 '방어막' 항목을 하나 push
2. 뒤로가기 → `popstate` 발생 → `handleAndroidBack()` 호출
3. 처리됐으면(`true`) 방어막을 다시 push → 앱 유지
4. 메인 화면이면(`false`) 방어막을 복구하지 않고 토스트만 표시 → **2초 안에 한 번 더 누르면 종료**

`handleAndroidBack()`의 처리 순서:
1. 열린 모달·오버레이 닫기
2. 날짜 패널 닫기
3. 메인이면 `false` 반환 (종료 신호)
4. **그 외에는 화면의 `‹` 버튼을 `click()`으로 누름**

4번이 핵심입니다. 페이지마다 돌아갈 곳이 다른데(카드 설정→내 지갑, 월별 상세→통계, 백업→설정), 예전에는 switch문으로 따로 관리하다가 여러 곳이 틀렸습니다. 이제 화면 버튼을 그대로 누르므로 **페이지를 추가해도 자동으로 맞습니다.** 새 페이지에는 `.page-header .back-btn`만 넣으면 됩니다.

### 8-2. PC 모드 (매번 공유 암호로 열기, 2026-09-19 추가)

**판정 (`TBDR_MODE`, 스크립트 맨 앞):** localStorage에 `tdbr_device_mode='local'`이 있거나, 기록(`tdbr_v3`, 빈 배열 제외)·공유 암호(`tdbr_sync_pass`)가 있으면 `'local'`. 이때 `tdbr_device_mode='local'`을 기록해 고정한다. 아무것도 없는 새 기기면 `'session'`.

**session 모드 흐름:**
1. `TBDR_UNLOCKED`가 false(이 탭에 공유 암호 없음)면 암호 화면(`#tbdr-gate`)을 띄운다.
2. `gateOpen()`: 이름·암호 → 서버 문서 읽기 → 복호화 → 백업 키들과 이름·암호·버전을 **sessionStorage에만** 넣고 새로고침. 암호가 다르면 문서 위치가 달라 "없음"으로 나오므로 "암호가 맞지 않거나 서버에 없음"으로 안내.
3. 열린 뒤: 헤더에 🔒 버튼, 설정의 [공유 설정] 자리에 [잠그기]. `sessionLock()`은 sessionStorage를 비우고 새로고침.
4. **자동 저장:** `save()`/`_lsSet()` → `markLocalDirty()` → `scheduleAutoUpload()`(1.2초 모음) → `sessionAutoUpload()`. 서버 버전이 더 크면(휴대폰이 먼저 저장) 올리지 않고 안내 후 `syncDownload()`로 넘긴다(사라질 PC 입력 목록 경고가 그대로 뜬다). 올리는 중 또 바뀌면 한 번 더 올린다. 실패하면 토스트만 띄우고 다음 변경 때 재시도.
5. **돌아오면 최신으로:** 탭이 다시 보이면 `sessionRefreshIfNewer()`가 서버 버전을 확인(30초에 한 번). PC에 안 올린 변경이 없고 메인 화면일 때만 조용히 교체한다(입력 중인 화면은 건드리지 않음).
6. 저장 대기 중 탭을 닫으면 `beforeunload` 경고. 앱이 스스로 새로고침할 때는 `window.__tbdrReloading = true`로 경고를 건너뛴다. **새로고침하는 코드를 추가하면 이 플래그를 꼭 세울 것.**

**PC 모드에서 막아 둔 것:** 전체 삭제(서버까지 비워짐), 공유 설정 변경. CSV 교체·백업 덮어쓰기는 `sessionBigChangeOK()`로 한 번 더 확인한다.

**화면 폭:** 8-3절의 넓은 화면 레이아웃이 적용된다.

### 8-3. 넓은 화면 레이아웃 (PC·가로 태블릿, 2026-09-19 추가)

## 10. 과거에 겪은 문제와 해결 (같은 실수 반복 방지)

### PWA가 설치되지 않고 바로가기만 생성됨 ★ 해결

원인은 `icon-512.png`의 **PNG 데이터 손상**이었습니다. `eXIf` 청크 CRC 불일치. 파일 헤더는 멀쩡해서 `file` 명령이나 육안으로는 구분되지 않았고, GitHub 업로드 과정에서 몇 바이트가 깨진 것으로 보입니다. 크기는 같은데 MD5만 달랐습니다.

안드로이드는 설치 시 구글 서버가 아이콘을 내려받아 검사하고 앱 아이콘을 만듭니다. 깨진 아이콘이면 WebAPK 생성이 실패하고 바로가기로 대체됩니다.

→ 아이콘을 교체할 때는 **CRC까지 검증**하고, GitHub에서 미리보기가 뜨는지 확인하세요. 부가 청크(`eXIf`, `caBX`) 없는 순수 PNG(IHDR/PLTE/IDAT/IEND)가 안전합니다. 현재 아이콘은 256색 팔레트로 재인코딩해 87KB/20KB입니다.

### 매니페스트 아이콘 선언 방식

같은 파일을 `purpose: any`와 `purpose: maskable`로 4줄 중복 선언했었습니다. 지금은 2줄 `"purpose": "any maskable"`입니다. `id` 필드는 넣지 않습니다. (같은 계정의 정상 동작하는 두 앱과 동일한 형식)

### 서비스워커 오프라인 대체 버그

실패한 모든 요청에 `index.html`을 돌려주고 있었습니다. 아이콘·매니페스트 요청에 HTML이 반환되어 설치 검사가 깨질 수 있습니다. 지금은 `req.mode === 'navigate'`일 때만 대체합니다. (v4)

### 상태 찌꺼기 버그

`openAddForm()`이 `selectedRecord`를 비우지 않아, 기록 상세를 봤다가 `+추가`를 누르고 뒤로가면 **엉뚱한 기록의 상세 화면**으로 갔습니다. 전역 상태를 쓰는 코드라 비슷한 함정이 또 있을 수 있습니다. 화면 진입 함수를 만들 때 **관련 없는 전역 상태를 반드시 초기화**하세요.

관련 전역: `records` `selectedDate` `selectedRecord` `detailFrom` `currentTab` `editingId` `formState` `panelSelectMode` `panelSelectedIds` `expandedCats` `lastEditedCat` `annualPageMode` `savedScrollPos`

### '오늘' 날짜가 앱 실행 시점에 고정됨 ★ 해결 (2026-09-19)

`today`/`todayStr`이 `const`여서, 안드로이드가 PWA를 며칠씩 살려 두면 + 버튼이 어제 날짜로 채워졌다. 지금은 `let`이고 `refreshTodayIfChanged()`가 `visibilitychange`와 1분 간격으로 갱신한다. **jsdom 테스트는 이 1분 타이머 때문에 저절로 끝나지 않으므로 마지막에 `process.exit()`를 호출할 것.**

### 서비스워커가 Firestore 통신을 캐시함 ★ 해결 (v5)

Firestore SDK는 GET 스트리밍 요청을 쓴다. v4는 모든 GET을 가로채 매 동기화마다 쓸모없는 응답을 캐시에 쌓았다. v5는 같은 출처와 `www.gstatic.com/firebasejs/`만 처리한다.

8. 다크 모드에서 확인했는가
9. 서비스워커를 고쳤다면 캐시 버전을 올렸는가
10. `localStorage`를 직접 쓰지 않고 `STORE`를 썼는가 (PC 모드 유출 방지)
11. 앱이 스스로 새로고침하는 코드를 넣었다면 `window.__tbdrReloading = true`를 먼저 세웠는가
12. 메인 화면을 바꿨다면 넓은 화면(1000px 이상)에서도 확인했는가

const {JSDOM}=require('jsdom');

## 13. 알려진 개선 여지

- **합치기가 수정·삭제를 전달하지 못함.** 기록에 `updatedAt`과 `deleted` 플래그를 추가하면 해결되지만 마이그레이션이 필요합니다.
- **저축·대출이 소분류 문자열 일치로 매칭됨.** 분류명을 바꾸면 연결이 끊깁니다. id 기반이 안전합니다.
- **localStorage 용량 한계.** 1만 건 근처에서 저장 실패 위험. IndexedDB 전환 고려.
- **`tbdr_settings_saved` 철자 통일.** 마이그레이션 코드를 넣으면 정리 가능.
- **동기화가 수동 (의도된 결정).** 자동 동기화는 사용자가 원하지 않아 넣지 않았다. 부담 없는 대안으로, 앱 실행 시 서버 version만 조회해 "새 내용 있음" 배지를 띄우는 방법이 있다. `updatedBy`/`updatedAt`은 평문이라 복호화 없이 조회 가능.
- **서버의 옛 문서.** 공유 암호를 바꾸면 새 문서가 생기고 옛 문서는 서버에 남는다(규칙상 delete 금지). 암호화돼 있고 목록 조회도 막혀 있어 실질 위험은 낮다. 지우려면 Firebase 콘솔에서 직접.
- **카드 이용기간이 전전월에 걸치는 카드**(예: 결제일 1일, 이용기간 전전월 18일~전월 17일)는 현재 모델로 표현할 수 없다. 저장 시 경고만 한다.
- **UI 문자열이 JS 문자열 연결이라 가독성이 낮음.** 큰 리팩터링은 위험하지만, 새로 만드는 화면만이라도 템플릿 리터럴을 쓰면 낫습니다.
- **당겨서 새로고침을 막아 수동 갱신 수단이 없음.** 설정에 "최신 버전 확인" 버튼을 두면 좋습니다.
